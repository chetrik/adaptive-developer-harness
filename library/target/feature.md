# feature

Мета користувача; scope/non-goals; acceptance criteria з IDs та перевірюваними умовою/дією/результатом (Given/When/Then або еквівалент); edge/error cases; релевантні NFR та спосіб перевірки або обґрунтоване N/A; критичні відкриті питання; джерело й погодження конкретної версії.

Для XS/S достатньо inline опису в поточній задачі, без окремого документа. Ризики не зникають через малий розмір. Якщо задача потребує формальних машинних доказів, агент запускає Spec/Readiness Gate генератора, а не самостійно виставляє PASS. Звичайний короткий цикл не потребує task JSON або формальних receipts; критичні невідомі вимоги й непогоджений scope блокують реалізацію незалежно від формату перевірки. Погодження встановлення Harness не є погодженням цієї специфікації.

Перед реалізацією коротко вкажи релевантні файли коду й рішення, обмеження, залежності задачі та фактичні команди перевірки з README/manifests/CI. Для кожного важливого критерію визнач ознаку готовності та відповідний тест або ручну перевірку. Посилання саме по собі не доводить прочитання: перевір наявність і актуальність критичних джерел, прочитай потрібні фрагменти. Використовуй чинну задачу або специфікацію, не створюй дублікати; для XS/S достатньо кількох рядків у чаті.

Це шаблон для заповнення, не свідчення виконання перевірок.
