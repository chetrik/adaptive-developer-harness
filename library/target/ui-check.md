# ui-check

Заповнюй лише релевантні пункти в наявній задачі; для маленької зміни достатньо короткого звіту, без окремого документа.

- Основний шлях: що користувач хоче зробити, які дії виконує і який видимий результат отримує. Для складного нового потоку спочатку узгодь простий прототип або послідовність екранів.
- Повторне використання: наявні компоненти, стилі й поведінка; не створюй дублікати кнопок, форм або таблиць без потреби.
- Стани: завантаження, порожні дані, успіх, помилки вводу й сервера, повторна спроба та недоступна дія — якщо релевантні.
- Доступність: клавіатура, видимий фокус, підписи полів і зрозумілі помилки; потрібні розміри екрана.
- Фактична перевірка: запусти застосунок дозволеним способом і пройди шлях у браузері, якщо інструменти доступні. Запиши кроки, очікуваний та отриманий результат, стан коду й обмеження. Скриншот підтверджує вигляд, але не роботу взаємодії.
- Недоступний браузер, зовнішній сервіс або потрібний доступ → відповідний сценарій not-verified із конкретним наступним кроком. Компіляція чи unit-тести не замінюють перевірку UI. Не використовуй production-дані й не виконуй ризикові дії без дозволу.

Це шаблон для заповнення, не свідчення виконання перевірок.
